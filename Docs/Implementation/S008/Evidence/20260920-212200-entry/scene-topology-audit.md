# Current scene/session audit
Source inspected: SessionFlow.cs, LootPopulationService.cs, LootAuthoring.cs, BuildUtility.cs, EditorBuildSettings.asset.
Scenes: S001Acceptance, CombatAcceptance, ZombieAcceptance, ScavengingAcceptance. Build settings currently enable S001Acceptance and CombatAcceptance; S006 authoring Build explicitly selects ScavengingAcceptance. No separate production open-world scene or menu scene was found among LastSignal scenes.
SessionFlow.Start begins the session in the loaded scene. Menu is an in-scene mode (Player absent), not a scene load. BeginSession creates Player, carried inventory, input and encounter, then LootPopulationService.Begin. ReturnToMenu ends loot/encounter and destroys Player. No runtime LoadScene or DontDestroyOnLoad usage found in LastSignal runtime.
LootPopulationService is scene/session owned: Begin is guarded by populated, resolves scene-local authored points once and creates Session Loot. End destroys generated and dropped items, clears results and permits a new session population. Calling End/Begin on shelter return would violate S008.
Recommended minimum: authored in-world shelter within a copy of ScavengingAcceptance. Preserve Player, scene, encounter, world items and loot population throughout expeditions. Only BeginSession/ReturnToMenu initialize/dispose shelter state. Do not add scene persistence or call loot Begin/End on leave/return. Partial world stacks and dropped items remain physically loaded.
