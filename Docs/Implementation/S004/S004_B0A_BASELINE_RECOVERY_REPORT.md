# S004-B0A: Baseline Recovery Report

## Executive Summary
The B0A baseline recovery has been successfully completed. 
The 8 PlayMode test failures were caused by test isolation and input system event propagation defects, NOT by broken production code. No production gameplay assertions were weakened, and no S004-P2/P3 zombie logic was implemented.

The project compiles, EditMode passes 34/34, PlayMode passes 21/21 (including a newly authored automated Runtime Smoke Test), and the Unity Editor is stable with no infrastructure aborts.

## Defect Analysis & Fixes

### 1. `IndexOutOfRangeException` (6 failures)
**Symptom:** `InputSystemUIInputModule.OnEnable` crashed with an out-of-bounds exception during test scene load, which corrupted the input system monitor arrays, cascading into tear-down failures across tests.
**Cause:** The Acceptance scenes contained active `EventSystem` GameObjects referencing the input package's stale `DefaultInputActions` singleton instead of the project's input actions. When the `InputTestFixture` resets the devices, the stale input action references crash.
**Fix:** Disabled the `EventSystem` GameObjects (`m_IsActive: 0`) in `CombatAcceptance.unity` and `S001Acceptance.unity`. Added a resilient `try-catch` to `CombatAcceptanceTests.TearDown()` to prevent cascading errors if cleanup fails.

### 2. Cascading Failures in `MovementAcceptanceTests`
**Symptom:** `CeilingRejectsStandThenAllowsNewRequestWithoutFootDrift` and `MouseAndCrouchActionsReachCameraAndCapsule` both failed.
**Cause:** Total test fixture contamination resulting from the `CombatAcceptanceTests` tear-down crash.
**Fix:** Once the `EventSystem` exception was resolved, these tests naturally passed. No changes were required to `PlayerStance.CanStand()` or `CharacterController` logic.

### 3. Combat Input Ignored
**Symptom:** Combat assertions failed (ammo didn't decrease) because mouse inputs generated by `InputTestFixture` were ignored.
**Cause:** `PlayerInputReader` was instantiated via scene loading, resolving its ActionMaps against the default OS devices. Then NUnit's `Setup()` wiped the InputSystem and added the mock test devices, leaving `PlayerInputReader` bound to the wiped devices.
**Fix:** Removed the `[UnitySetUp]` attribute from `LoadCombatScene` and explicitly yielded it at the beginning of each Combat test coroutine. Manually invoked `Awake()` via reflection inside `LoadCombatScene` after the player instantiated to explicitly bind the component to the mock devices, and ensured `neutralRequired` had time to clear before simulating inputs.

### 4. Combat Hit Detection Misses
**Symptom:** Fire and AutoFire tests correctly fired the weapon (ammo decreased) but recorded 0 damage to the target.
**Cause:** `CombatAcceptanceTests` aimed the camera using `look.transform.LookAt(target10m.transform.position)`. The target position corresponds to the base of the capsule (Y=0), while the camera is at Y=1.6. The raycast was shooting downward into the floor.
**Fix:** Appended `+ Vector3.up * 1.5f` to the LookAt target position so the camera correctly aims at the target's chest.
