# Freeze and ownership proposal (not implemented)
Preserve S004 combat/player/AI, S005 inventory contract, S006 loot RNG/population and S007 reserve/reload authority. New S008 components should own only stash and within-session expedition lifecycle.
PlayerInventory owns carried items; ShelterStorage owns stored items; weapon owns loaded rounds; WorldItem owns physical quantity; UI owns no quantity.
PlayerInventory currently combines array stack operations and MonoBehaviour drop integration. No reusable lower-level container exists. Minimum reuse requires a small shared container extraction or composition; copying stack algorithms into a second inventory engine is prohibited. Existing public PlayerInventory methods must remain compatible. Two-container transfer must commit both states before any change events and guard callback reentry. Existing TryAdd/Remove independently notify, so naive chaining is not atomic to observers.
Lifecycle: Shelter -> Preparing -> Shelter -> Expedition -> Shelter, monotonically increasing expedition index, idempotent rejected duplicate requests; no application-session restart. In-world explicit interactions use IInteractable, range and current session/player checks. Preserve physical safety via authored building/door geometry, never global AI freezing or invulnerability. Existing inventory preparation uses SessionFlow pause/input/cursor policy; integrate one modal owner and test close/death/menu/pause before acceptance.
Assumptions pending baseline: fixed configurable 48-slot stash (carried remains 24); empty initial stash, no free ammo; starting magazine 30 and reserve 0 unchanged. Acceptance can first scavenge/store and then withdraw; fixture supplies must not enter production defaults. No death penalty, healing, disk save, crafting, construction or survival needs.
